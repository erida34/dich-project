# ADR 0007 — Cache durability and rollback journal

Status: Proposed; implementation has not been verified.

Cache data is disposable but authenticity and rollback state are not. Treat the cache root as an explicitly configured local directory, open each component without following symlinks and reject unsafe ownership or group/other write permission. Do not use a network filesystem unless its locking, rename and fsync semantics are independently established. Locks are per canonical source-policy identity and held over read, validation and publication; failures or contention must be explicit.

Maintain a source rollback floor containing the latest accepted signed Release date, its digest and latest trusted wall time. Reject an older Release, different content at the same signed date, and backwards time. The source identity includes distribution, normalized URI, configured suite and architecture with unambiguous length framing. Components and signing-key configuration are deliberately excluded: reordering or narrowing an imported source or rotating its key must not reset the rollback floor. Different configured suite aliases may still create separate floors and require policy work before production. A trusted clock and protected cache root are prerequisites; deletion or rollback of the entire floor and malicious modification by the same trusted user remain outside this initial boundary.

Write staged records within the open cache directory, fsync each file, atomically rename it, and fsync the containing directory. For artifacts, publish verified content first, sync it and its directory, then publish metadata referencing it; interrupted updates may leave unreachable files, never a trusted partial object. Recheck content size and digest on every cache read and reverify signed metadata under current key policy and freshness requirements. A failure after rename but before directory fsync is an uncertain commit: report failure and require a fresh read before further work. Do not claim power-loss durability solely from code review. Add concurrency and failure-injection tests for each publication boundary, plus corruption, symlink and expiration tests. Index/source caching, durable artifact storage and integration with fetch are not yet implemented.

A returned in-memory snapshot pin can become stale if another process advances the floor. Before using it to authorize a download or cached object, the final design must recheck the current floor under the appropriate lock; the provisional journal API is not yet an authorization gate.
