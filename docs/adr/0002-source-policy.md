# ADR 0002 — Explicit source policy and deb822 import

Status: Accepted for the initial source configuration slice. The operator also explicitly declares whether the source belongs to Debian or Ubuntu; this is an assertion to validate against signed metadata in a later milestone, not a hostname-based inference.

A source is an exact repository URI, one suite, a nonempty component set, one architecture, and explicit signing trust: an absolute keyring path and one or more full OpenPGP fingerprints. The operator supplies this policy independently of the imported `.sources` file. Import may only narrow the configured components; it cannot add an origin, suite, architecture, keyring, or signing fingerprint. A `Signed-By` keyring is mandatory and must match the policy. Fingerprints in that field, if present, further restrict the policy; if absent, the policy's fingerprints apply. Fingerprints are 40 or 64 hexadecimal characters and compared case-insensitively. A primary fingerprint permits its signing subkeys unless `!` is specified, as in APT; enforcement belongs to signature verification and is not implemented by the importer.

The first implementation accepts bounded UTF-8 deb822 files, comments, folded fields, and multiple stanzas. It accepts binary (`deb`) repositories only; disabled stanzas are skipped. Unsupported options and ambiguous or malformed input fail closed. URI text is restricted to an explicit conservative HTTPS form and is matched exactly against the operator's policy. No URL is fetched by this slice. Future network code must independently parse URLs, enforce redirect/origin policy and avoid interpreting configuration validation as authorization to skip signature verification.

This is configuration, not a trust decision about downloaded data: it neither reads keyrings nor verifies signatures, freshness, checksums or distribution metadata. Imported sources are not available through the CLI until later milestones. Configuration storage, multi-suite expansion, inline OpenPGP keys, `deb-src`, flat repositories and general APT option compatibility remain unsupported. The caller is responsible for securely loading operator policy and input; keyring ownership, symlink/race resistance and key fingerprint binding must be addressed before repository verification.
