# ADR 0038 — Release Artifacts, Architecture Policy, and Release Distribution

Status: Accepted for Phase 7 public release.

## Context

Shipping production releases of Dich requires verified release artifact generation, clear platform architecture boundaries, cryptographic integrity verification, and explicit release asset management.

The project roadmap requires:
> Release artifacts for amd64; arm64 only after verified, SHA256SUMS, release notes and verified GitHub Release assets.

## Decision

### 1. Primary Release Architecture (`amd64`)
- The primary supported release architecture for Dich v0.7.x / v1.0 is **Linux `amd64` (x86_64)**.
- Each release tag (`v*`) triggers an automated build on Ubuntu GitHub-hosted runners producing:
  - `dich_<upstream-version>-<debian-revision>_amd64.deb` conforming to Debian packaging standards (for example, `dich_0.1.0-1_amd64.deb`).
  - Executable `/usr/bin/dich`.
  - Manual pages in `/usr/share/man/man1/` (19 man pages).
  - Shell completion scripts installed in standard system vendor paths:
    - Bash: `/usr/share/bash-completion/completions/dich`
    - Zsh: `/usr/share/zsh/vendor-completions/_dich`
    - Fish: `/usr/share/fish/vendor_completions.d/dich.fish`
  - License and documentation files in `/usr/share/doc/dich/`.
- Build the release executable on Ubuntu 22.04 (glibc 2.35), the oldest declared supported baseline. A local package built on Ubuntu 24.04 inferred `libc6 (>= 2.39)`, which excludes Ubuntu 22.04 and Debian Bookworm; container smoke tests must verify the Jammy-built package's inferred dependency before release.

### 2. ARM64 Architecture Policy
- ARM64 (`aarch64`) release artifacts are **deferred** until dedicated native ARM64 runners or a verified reproducible cross-compilation pipeline with clean QEMU/container smoke tests is established.
- No untested or unverified ARM64 binaries will be published to GitHub Releases.

### 3. Checksums, SBOM, and Provenance
Every release automatically produces and publishes the following assets to GitHub Releases:
- `dich_<upstream-version>-<debian-revision>_amd64.deb`: Binary Debian package.
- `SHA256SUMS`: Cryptographic SHA-256 checksum manifest of all release files.
- `dich.spdx.json`: Machine-readable SPDX 2.3 Software Bill of Materials.
- Cryptographic provenance attestation generated by GitHub Actions (`actions/attest-build-provenance`).

### 4. Release Verification Workflow
Before release publication, `.github/workflows/release.yml` executes containerized smoke tests in amd64 Debian 12 Bookworm, Debian 13 Trixie, Ubuntu 22.04 Jammy, and Ubuntu 24.04 Noble OCI manifests pinned by digest. It verifies installation, documentation and license presence, package reinstallation, CLI execution, and clean removal. The local distro tags in the CI workflow may move; release-gate image references are immutable manifest digests.

## Consequences

- Dich releases remain predictable, secure, and verifiable.
- Avoids releasing untested cross-compiled architectures.
