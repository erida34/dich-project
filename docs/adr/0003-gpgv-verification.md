# ADR 0003 — Verify repository signatures with isolated gpgv

Status: Proposed; implementation and security verification in progress.

Use the system's `/usr/bin/gpgv` on Linux with structured arguments, a private temporary home and only a caller-provided binary keyring, never a shell or the host default keyring. The caller must obtain keyring bytes from the configured path through a trusted, race-resistant mechanism; source policy and keyring access are separate from cryptographic verification. Restrict input sizes, processing time, output, and supported signature forms, fail on gpgv errors and malformed or ambiguous status, and require the cryptographically reported signing or primary fingerprint to match the independently configured `Signed-By` policy. With a `!` suffix only the exact signing fingerprint is allowed.

Both clearsigned InRelease and detached Release plus Release.gpg must be tested with generated fixture keys and hostile mutations. A verified signature alone does not establish the suite, expiry, freshness, anti-rollback policy, index or package integrity. These remain later gates. The helper and its host binary are trusted computing base; a hostile same-user process or privileged attacker able to alter the runtime, temporary directory or gpgv executable is outside this initial helper boundary and must be addressed in the privilege/security review. GnuPG version compatibility and key expiration/revocation behavior require explicit tests before this decision can be accepted.
