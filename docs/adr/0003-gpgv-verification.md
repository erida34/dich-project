# ADR 0003 — Verify repository signatures with isolated gpgv

Status: Accepted for the library-only signature verification slice, with the limitations below.

Use Linux `/usr/bin/gpgv` through `/usr/bin/prlimit`, with structured arguments, a private temporary home and only the configured binary keyring, never a shell or the host default keyring. Component-by-component `openat` with `NOFOLLOW` anchors keyring access; each directory and the regular keyring must be owned by root or the effective user and must not be writable by group or others. The caller must securely open operator policy and source input. Restrict input sizes, processing time, output, and supported signature forms, fail on gpgv errors and malformed or ambiguous status, and require the cryptographically reported signing or primary fingerprint to match the independently configured `Signed-By` policy. With a `!` suffix only the exact signing fingerprint is allowed. The byte-level verification primitives are internal to the crate.

Both clearsigned InRelease and detached Release plus Release.gpg are tested with generated fixture keys and hostile mutations, including expired and revoked keys. GnuPG 2.4.4 additionally verified a cached Ubuntu noble InRelease. A verified signature alone does not establish the suite, Release expiry, freshness, anti-rollback policy, index or package integrity. These remain later gates. The helpers and their host binaries are trusted computing base; a hostile same-user process or privileged attacker able to alter the runtime, temporary directory, opened files or helper executables is outside this initial boundary and must be addressed in the privilege/security review. Other GnuPG/util-linux versions, resource-limit stress, and full distribution integration remain unverified. Multiple signatures are accepted only when every signature is valid and every signer is explicitly allowed; missing keys or unauthorized signers fail closed.
