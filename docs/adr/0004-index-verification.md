# ADR 0004 — Signed index checksums and bounded decompression

Status: Accepted for the library-only index verification slice.

Packages index integrity must start from `VerifiedRelease`, bound to the source policy used during signature verification. Derive the index path from an allowed component and the configured architecture; never accept a caller-provided checksum or arbitrary index path. Parse the signed `SHA256` section strictly, reject duplicate matching paths, malformed checksums and sizes, missing entries and unsupported formats. Check the compressed byte count and SHA256 before attempting decompression.

Support gzip and xz via fixed system executables under `prlimit`, with explicit compressed and expanded byte limits, a 64 MiB xz decoder memory limit, CPU and wall-time limits. Defaults are 64 MiB compressed and 256 MiB expanded; callers may set lower or higher limits within the documented hard ceilings. Reject truncated and malformed streams, trailing junk and decompression bombs; valid format-defined padding or concatenated streams follow the system decoder's behavior. The current API takes compressed bytes and returns decoded bytes in memory, so callers must bound network reads and available memory; true streaming into an index parser is future work. Helpers have been exercised in Ubuntu WSL and in a temporary chroot on `dich-root` using copied Ubuntu runtime binaries, not Debian-packaged helper versions. Signed metadata is still untrusted input: signature verification alone does not prove suite identity or freshness. Index verification is not permission to install packages. Release freshness and rollback policy remain later work.
