# ADR 0019 — Immutable reference graph snapshots (proposed)

Status: Accepted for experimental library-only graph snapshots.

A dependency resolution is contextual: a store object may participate in several different dependency closures. Do not attach one mutable dependency list directly to a content identity. A graph snapshot is a separately identified, canonical representation of explicit root tree identities and directed edges between published tree identities. Cycles are permitted; a self-edge is rejected. Exact duplicate edges and roots are rejected to expose ambiguous inputs. All identifiers use lowercase SHA256 hex and each referenced node must already have a committed tree metadata record. An isolated root is a valid graph. Graph contents are bounded; a deterministic, domain-separated encoding and SHA256 identify the snapshot.

Creation must validate the complete graph before writing and commit the snapshot and its edges as one SQLite WAL/FULL transaction under the existing exclusive store lock. Reuse compares canonical bytes, not just the hash. Schema v4 stores canonical snapshots and indexed members in one transaction with foreign keys; reuse checks both canonical bytes and membership. Explicit orphan cleanup also checks graph membership, even for dangling rows. Graph storage does not authenticate stored bytes, establish ABI compatibility, create a profile, pin objects for GC, or authorize execution. Graph records currently have no deletion API. Before any GC or object deletion is introduced, all graph reference semantics and future roots must be integrated; the existing orphan removal continues to reject every registered tree regardless of graph membership. Same-UID adversaries and physical power loss remain outside demonstrated guarantees.

Acceptance: deterministic identity regardless of input order; isolated roots and cycles; reject malformed IDs, duplicates, self-edges, missing nodes and non-root disconnected components; atomic rollback on simulated failure; reopen/reuse; collision rejection; no metadata referring to uncommitted trees. Inspect and full byte verification are separate features and remain pending.

Read-only verification design: the verifier must use the protected store lock, require a committed object row and a well-formed identifier, recompute the identity digest over its stored canonical identity, parse bounded tree manifests strictly, and compare every file and directory against the persisted manifest with no link following. Archive verification hashes all bytes against the committed digest. It returns only verification against local metadata; it is not fresh repository authentication, ABI analysis, activation or hard immutability. Missing or altered entries, malformed manifests, extra files and dangerous file modes must fail closed. Read-only inspection must not create store directories, copy files, fsync objects or change database records.

Object inspection and listing return bounded committed metadata records (identity, object kind and recorded byte count). They do not open content and must never label it verified. Separate archive/tree verification compares bytes with local metadata. Graph readback strictly decodes canonical bytes, rechecks the graph digest and membership, and validates the local identities of all referenced trees; it does not verify their contents. CLI integration is a subsequent roadmap item.
