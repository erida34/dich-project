# ADR 0011 — Resolver search boundary (work in progress)

Status: Proposed.

A deterministic bounded backtracking engine operates on opaque candidate identities and requirements supplied by a provider. The provider must return matching candidates in explicit deterministic preference order, declare pairwise incompatibility, supply each candidate's requirements, and reject unsupported semantics before planning. The engine never reads dpkg state and cannot establish repository authenticity or ABI compatibility; an APT adapter must build its input exclusively from reauthenticated, fresh, policy-matched indices. Search exhaustion and resource limits have distinct errors; neither may be reported as a valid plan. Cycles may be satisfied by already selected candidates, but Pre-Depends cycle semantics and activation ordering require explicit checks before any plan claims support. The initial CLI must label a result as a plan, never an installation or compatibility guarantee. Candidate provenance and immutable lock/plan identity remain the following roadmap item.

A preliminary in-memory Debian fixture provider checks version constraints and versioned virtual provides, orders alternatives, detects declared conflicts/breaks, and excludes essential/required, Pre-Depends, multiarch and architecture/profile restriction cases. It is not an authenticated adapter or production planner; it conservatively distinguishes encountered unsupported candidates from proven unsatisfiability, but does not pin provenance or establish adequate resource limits for a full repository. Duplicate name/version records fail closed. A bounded name index and option cap reduce search work, but those gaps must be resolved before CLI integration.

An experimental loader now constructs one in-memory dataset from a source cache only after revalidating Release signatures, freshness, source policy and signed index hashes. It checks for a changed Release during loading. The object can produce a limited informational plan after rechecking the Release and indices before and after the search. CLI plans require exactly one source and explicit distribution, suite and architecture. They are not pinned to artifacts and do not prove installability. Provenance pinning and multi-source semantics remain unimplemented. Cache updates are not a globally atomic snapshot.

The CLI emits `planned` metadata-only results, or distinct `unsupported`, `unsatisfiable`, `search_limit` and cache/policy errors. Traces are bounded and include candidate consideration, conflict pairs, previously selected requirements and backtracking. Pre-Depends, multiarch qualifiers and essential/required candidates are rejected; this is not a complete Debian resolver.
